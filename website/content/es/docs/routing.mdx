# Enrutado

DaloyJS usa un trie de segmentos (árbol de prefijos por segmento) con una ruta rápida para las rutas estáticas. Tras las comprobaciones de seguridad de la ruta, las rutas estáticas exactas se resuelven con una única llamada a `Map.get`. Las búsquedas dinámicas prefieren los segmentos literales, después los parámetros y, por último, los comodines. Una búsqueda sin retroceso (backtracking) es lineal respecto a la longitud de la ruta, pero las rutas que se solapan pueden obligar a visitar ramas adicionales del trie.

Solo cuentan como coincidencias las rutas completas. Por ejemplo, registrar `/users/me/details/:field` no impide que `/users/me` coincida con `/users/:id`. Dentro del trie dinámico, una ruta completa de mayor prioridad gana aunque no tenga un handler para el método solicitado. Una ruta estática exacta gana para los métodos con los que se registró; otros métodos pueden seguir coincidiendo con el trie dinámico.

## Atajos progresivos [#progressive-shorthands]

Los atajos por método reducen el código repetitivo sin quitar el contrato. DaloyJS deriva un identificador de operación estable a partir del método y la ruta, como `getRoot` o `postBookItemsByItemId`. Un `operationId` explícito siempre tiene prioridad.

```ts
const app = new App()
  .get(
    "/",
    { responses: { 200: { body: z.object({ hello: z.string() }) } } },
    () => ({ status: 200, body: { hello: "world" } }),
  )
  .post(
    "/books",
    {
      request: { body: z.object({ title: z.string().min(1) }) },
      responses: {
        201: { body: z.object({ id: z.string() }) },
      },
    },
    ({ body }) => ({ status: 201, body: { id: "book_1" } }),
  );
```

Los atajos mantienen el mismo comportamiento de validación, OpenAPI, seguridad y cliente tipado que `route()`. No existe ninguna forma de dos argumentos que omita en silencio un contrato de respuesta. Para un cuerpo que deliberadamente no tiene esquema, pasa `acknowledgeNoResponseBodySchema: true` de forma explícita. Las respuestas sin procesar exitosas devueltas por `preBody` o `beforeHandle` requieren la misma confirmación. Las denegaciones ordinarias de los hooks con `4xx`/`5xx` no la requieren. Las descripciones de respuesta siguen siendo opcionales. Si se omiten, OpenAPI usa una descripción estable del tipo `HTTP <status> response`.

## Definir rutas [#defining-routes]

Una declaración de ruta es la fuente de verdad para el emparejamiento, la validación de peticiones, la validación de respuestas, la salida de OpenAPI y los clientes tipados. Escribe las rutas con los atajos por método (`app.get(path, contract, handler)`, `app.post(...)`, `app.put(...)`, `app.patch(...)`, `app.delete(...)`, `app.head(...)`). Estos atajos derivan un `operationId` automáticamente, y un `operationId` explícito siempre tiene prioridad. DaloyJS rechaza los valores `operationId` duplicados en el momento del registro.

```ts
import { App } from "@daloyjs/core";
import { z } from "zod";

const UserSchema = z.object({
  id: z.uuid(),
  email: z.email(),
  tenantId: z.string(),
  included: z.enum(["profile", "settings"]).optional(),
});

async function loadUser(input: {
  id: string;
  tenantId: string;
  include?: "profile" | "settings";
}) {
  return {
    id: input.id,
    email: "dev@example.com",
    tenantId: input.tenantId,
    included: input.include,
  };
}

export const app = new App().get(
  "/users/:id",
  {
    operationId: "getUser",
    tags: ["Users"],
    summary: "Get a user by id",
    request: {
      params: z.object({ id: z.uuid() }),
      query: z
        .object({ include: z.enum(["profile", "settings"]).optional() })
        .optional(),
      headers: z.object({ "x-tenant": z.string() }),
    },
    responses: {
      200: { description: "Found", body: UserSchema },
      404: { description: "Not found" },
    },
  },
  async ({ params, query, headers }) => {
    // params, query y headers se infieren de los esquemas de arriba.
    return {
      status: 200,
      body: await loadUser({
        id: params.id,
        tenantId: headers["x-tenant"],
        include: query?.include,
      }),
    };
  },
);
```

### La forma de objeto: `app.route({...})` [#route-object-form]

`app.route({ method, path, ...contract, handler })` recibe el mismo contrato en un único objeto. El comportamiento en tiempo de ejecución, la validación, la seguridad y la salida de OpenAPI son idénticos a los de los atajos. Úsala solo cuando necesites la ruta como un valor: un contrato reutilizable con `defineRoute()` (consulta [Inferencia de tipos entre varios archivos](#multi-file-type-inference)), una ruta `OPTIONS` (que no tiene atajo) o un objeto de ruta construido por otro código. Con `route()`, indica tú mismo un `operationId` para cualquier ruta pública que quieras en el cliente tipado.

```ts
app.route({
  method: "OPTIONS",
  path: "/books",
  operationId: "booksOptions",
  responses: { 204: { description: "Allowed methods" } },
  handler: ({ set }) => {
    set.headers.set("allow", "GET, POST, OPTIONS");
    return { status: 204, body: undefined };
  },
});
```

## Inferencia de tipos entre archivos [#multi-file-type-inference]

Exporta cada ruta con `defineRoute()` y, después, combina los contratos importados mediante `registerRoutes()`. La tupla literal se conserva al cruzar los límites de archivos y módulos, así que el cliente sin generación de código mantiene todos los identificadores de operación y todos los esquemas.

```ts
// routes/list-books.ts
export const listBooksRoute = defineRoute({
  method: "GET",
  path: "/books",
  operationId: "listBooks",
  responses: {
    200: { description: "Books", body: z.array(z.object({ id: z.string() })) },
  },
  handler: async () => ({ status: 200, body: [{ id: "1" }] }),
});

// app.ts
import { listBooksRoute } from "./routes/list-books.js";
import { createBookRoute } from "./routes/create-book.js";

export const app = new App().registerRoutes([
  listBooksRoute,
  createBookRoute,
] as const);
```

Encadenar llamadas a `route()` también acumula los tipos correctamente. Evita una anotación `const app: App` en la aplicación final compuesta, porque amplía explícitamente la tupla de rutas y la pierde.

Los `group()` con callback y el `register()` de los plugins siguen aportando un ámbito en tiempo de ejecución, pero TypeScript no puede ampliar la variable padre desde dentro de sus callbacks. Para tener un cliente totalmente tipado y sin generación de código en módulos grandes, exporta tuplas de rutas literales y usa `registerRoutes()` como el límite final de composición.

## Métodos HTTP [#http-methods]

Los métodos admitidos son `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD` y `OPTIONS`. Los métodos personalizados, como `TRACE`, `CONNECT` y los verbos de WebDAV, se rechazan durante el registro.

`HEAD` recurre a la ruta `GET` correspondiente cuando no existe una ruta `HEAD` explícita, y devuelve las mismas cabeceras con un cuerpo vacío. `OPTIONS` devuelve una respuesta 204 de preflight con una cabecera `Allow` cuando la ruta existe, pero no hay ninguna ruta `OPTIONS` explícita registrada.

Los atajos por método están disponibles para `GET`, `POST`, `PUT`, `PATCH`, `DELETE` y `HEAD`. Para registrar una ruta `OPTIONS` explícita, usa `route()`. Si no lo haces, DaloyJS gestiona el preflight automáticamente.

## Parámetros de ruta [#path-parameters]

```ts
app.get(
  "/orgs/:org/repos/:repo",
  {
    operationId: "getRepo",
    request: {
      params: z.object({ org: z.string(), repo: z.string() }),
    },
    responses: {
      200: {
        description: "Repository",
        body: z.object({ org: z.string(), repo: z.string() }),
      },
    },
  },
  async ({ params }) => ({ status: 200, body: params }),
);
```

Los valores de la ruta se decodifican antes de la validación. Si omites el esquema `request.params`, `ctx.params` se infiere a partir de la ruta como cadenas sin procesar. Los nombres de parámetro en conflicto en la misma posición del trie, como `/a/:x` y `/a/:y`, lanzan un error durante el registro.

Los nombres de captura deben ser cadenas no vacías y únicos dentro de cada ruta. Los nombres `__proto__`, `constructor` y `prototype` se rechazan para que los objetos de parámetros sean seguros para su uso posterior. Un registro rechazado no reserva su `operationId`.

### Capturas con comodín [#wildcard-captures]

Un segmento final `*name` captura el resto de la ruta en una única cadena decodificada y exige que quede al menos un segmento. Un `*` sin nombre usa el nombre `wildcard`. Los comodines deben estar al final: `/assets/*path/private` lanza un error durante el registro en lugar de coincidir en silencio con una ruta más amplia. Varios métodos pueden compartir una ruta con comodín siempre que el nombre de la captura coincida. Los métodos duplicados y los nombres de comodín en conflicto lanzan un error.

```ts
app.get(
  "/assets/*path",
  {
    operationId: "getAsset",
    request: { params: z.object({ path: z.string() }) },
    responses: {
      200: { description: "Asset", body: z.object({ path: z.string() }) },
    },
  },
  async ({ params }) => ({ status: 200, body: params }),
);

// GET /assets/css/app.css -> params.path === "css/app.css"
```

Los segmentos de recorrido de ruta sin procesar (`..`), los segmentos vacíos `//` y los escapes porcentuales mal formados en las capturas no coinciden y devuelven un fallo limpio. La detección de métodos aplica las mismas comprobaciones, así que las rutas rechazadas no anuncian una cabecera `Allow`. Desde la versión 1.3.7, un segmento de parámetro o de comodín nunca se vincula a `.` ni a `..`, incluidas las formas codificadas `%2e` y `%2e%2e`. Un analizador de URL resolvería esos valores como pasos de directorio, así que permitir su vinculación daría al handler una ruta distinta de la que vio el middleware. Una captura también rechaza un valor decodificado que tenga un componente `.` o `..` detrás de un separador codificado (`..%2F..%2Fsecret`, `..%5C`), o cualquier carácter de control (`%00`, `%0A`, `%09`, `%7F`). Esas peticiones reciben un `404`.

Por defecto, una captura que decodifica un `/` o un `\` codificados (`%2F`, `%5C`) también se rechaza con un `404`, porque un único valor capturado abarcaría entonces varios segmentos de ruta para cualquier consumidor posterior, sea un sistema de archivos, una URL o un proxy. Si una ruta necesita de verdad identificadores con barras, actívalo de forma explícita para esa ruta:

```ts
app.get(
  "/books/:id",
  {
    allowEncodedSlash: true, // GET /books/book%2F1 -> ctx.params.id === "book/1"
    responses: { 200: { description: "Book" } },
  },
  (ctx) => ({ status: 200, body: { id: ctx.params.id } }),
);
```

Activar esta opción nunca vuelve a admitir componentes `..` ni caracteres de control. Los parámetros decodificados siguen siendo datos no confiables y no son rutas de sistema de archivos saneadas, así que la validación del acceso al sistema de archivos debe hacerse por separado.

Los adaptadores también mantienen una única vista de la ruta para el enrutador y el middleware (desde la versión 1.3.7). El adaptador de Node canonicaliza los request-targets que contienen `\`, segmentos de punto o sus formas `%2e` como lo haría `new URL()`, antes de enrutar. Los adaptadores de Node y de AWS Lambda rechazan con `400` cualquier cabecera `Host` que no sea un simple `host[:port]` (por ejemplo, una que contenga `\ / ? # @ %` o espacios en blanco). Así, las guardas basadas en la ruta, como `except()`, coinciden exactamente con la ruta que se ejecuta. Consulta el [adaptador de Node](/docs/adapters/node) (en inglés) para más detalles.

## Grupos [#groups]

```ts
app.group("/api/v1", { tags: ["v1"] }, (v1) => {
  v1.get(
    "/health",
    {
      operationId: "health",
      responses: {
        200: { description: "ok", body: z.object({ ok: z.boolean() }) },
      },
    },
    async () => ({ status: 200, body: { ok: true } }),
  );
});
// ruta final: /api/v1/health
```

Los grupos combinan prefijos, etiquetas, hooks y valores predeterminados de autenticación en las rutas registradas dentro del callback. La aplicación hija está encapsulada: el middleware añadido dentro de un grupo no se filtra a las rutas que están fuera de él. Las rutas agrupadas son visibles para el enrutamiento en tiempo de ejecución y para OpenAPI. Para contratos paralelos `/api/v1` y `/api/v2`, la política de migración y los SDK generados por separado, consulta la [guía de versionado de la API](/docs/api-versioning) (en inglés).

## Opciones de ruta [#route-options]

- `request`: esquemas para `params`, `query`, `headers` y `body`.
- `responses`: códigos de estado declarados y esquemas opcionales del cuerpo y de las cabeceras de la respuesta.
- `accepts`: lista de tipos `Content-Type` permitidos por ruta, para las rutas con esquemas de cuerpo de petición.
- `auth`: requisito de seguridad de OpenAPI para la ruta. Combínalo con un hook de autenticación, como `bearerAuth()`.
- `internal`: oculta una ruta de los adaptadores públicos, pero sigue permitiendo las llamadas `app.inject()` dentro del proceso.
- `deprecated` y `sunset`: marcan un endpoint como obsoleto y emiten las cabeceras de respuesta correspondientes.
- `callbacks` y `meta`: añaden callbacks de OpenAPI, ejemplos y metadatos de ruta pensados para la IA.

## Hooks [#hooks]

Los hooks añaden comportamiento en puntos fijos del ciclo de vida:

- `onRequest`: el primero, antes del análisis (parsing).
- `preBody`: después de la coincidencia de la ruta y antes de la validación del esquema o de la E/S del cuerpo. La autenticación integrada por cabecera, JWT, básica y mTLS se ejecuta aquí.
- `beforeHandle`: después de la validación y antes de tu handler. Devuelve una `Response` para cortocircuitar el flujo.
- `afterHandle`: envuelve o transforma el resultado del handler antes de serializar la respuesta.
- `onError`: observa o reemplaza la respuesta de error.
- `onSend`: modifica las cabeceras de salida en su lugar o devuelve una nueva `Response`. Se ejecuta en las rutas de éxito, de error y de preflight `OPTIONS`.
- `onResponse`: observador final. Úsalo para registros (logging) y métricas. No modifiques la respuesta en este punto.

```ts
  async () => ({ status: 200, body: { purged: true } }),
);
```

## Transformar respuestas con `onSend` [#transforming-responses-with-onsend]

Usa `onSend` cuando necesites reescribir la respuesta de salida, por ejemplo, para añadir una cabecera, eliminar una cabecera interna o reemplazar la respuesta por completo. Si devuelve `void`, se mantiene la respuesta actual. Varios hooks `onSend` se componen como una cadena (global → grupo → ruta).

```ts
const app = new App({
  hooks: {
    onSend(res) {
      // Anuncia siempre la versión de la API en cada respuesta saliente,
      // incluidas las respuestas de error y los preflight OPTIONS.
      res.headers.set("x-api-version", "2026-05-15");
    },
  },
});

app.get(
  "/users/me",
  {
    operationId: "me",
    hooks: {
      onSend(res) {
        // Quita detalles internos de implementación antes de que salga la respuesta.
        res.headers.delete("x-internal-cache-key");
      },
    },
    responses: {
      200: { description: "ok", body: z.object({ id: z.string() }) },
    },
  },
  async ({ set }) => {
    set.headers.set("x-internal-cache-key", "shard-a");
    return { status: 200, body: { id: "u_1" } };
  },
);
```

`onSend` se ejecuta *después* de la validación de la respuesta y después de combinar las cabeceras con alcance de petición, incluida `x-request-id`. Se ejecuta *antes* de `onResponse`, que sigue siendo el lugar adecuado para los registros (logging) y las métricas.

## 405 Method Not Allowed [#405-method-not-allowed]

Si una ruta está registrada para un método, pero se llama con otro, el enrutador devuelve **405** con una cabecera `Allow` correcta, nunca un 404 engañoso. Las rutas marcadas con `internal: true` se excluyen de las respuestas 405 públicas y de las cabeceras `Allow`, para que los endpoints de administración o de tareas programadas ocultos no se revelen al sondear métodos.

La detección de métodos incluye tanto una ruta estática exacta como la ruta dinámica seleccionada. Con `GET /users/me` y `POST /users/:id`, la ruta `/users/me` anuncia los dos métodos registrados. La cabecera enumera los registros explícitos; el manejo sintetizado de HEAD y OPTIONS no añade entradas.
