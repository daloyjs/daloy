# Especificación OpenAPI de DaloyJS

DaloyJS genera un documento **OpenAPI 3.1** limpio directamente desde tus definiciones de rutas, sin plugins ni decoradores aparte. La validación, los tipos y la especificación comparten una única fuente de verdad.

## Una línea: monta automáticamente /docs, /openapi.json y /openapi.yaml [#one-line-auto-mount-docs-openapi-json-openapi-yaml]

Al estilo de FastAPI. Pasa `docs: "auto"` (o `docs: true`) al constructor de `App` y DaloyJS registra por ti `GET /openapi.json` y `GET /openapi.yaml` (la especificación actualizada en ambos formatos) y `GET /docs` (una referencia de la API con Scalar).

```ts
import { App } from "@daloyjs/core";

const app = new App({
  openapi: {
    info: { title: "My API", version: "1.0.0" },
    servers: [{ url: "https://api.example.com" }],
    securitySchemes: { bearer: { type: "http", scheme: "bearer" } },
  },
  docs: "auto", // monta GET /docs, GET /openapi.json y GET /openapi.yaml fuera de producción
});
```

`docs: "auto"` solo se monta cuando la App no está en producción (las plantillas de `create-daloy` usan este valor por defecto, para que una API desplegada no publique su esquema), o déjalo desactivado (valor por defecto) y móntalo a mano con los helpers de abajo. Personaliza las rutas, la interfaz y las etiquetas mediante la forma de objeto. Desde la versión 1.5.5, la forma de objeto se comporta como `"auto"` a menos que definas `enabled`, así que personalizar la interfaz nunca publica por accidente el mapa de rutas en producción. Define `enabled: true` (o `docs: true`) para una API pública que debe servir su documentación en producción:

```ts
new App({
  openapi: { info: { title: "My API", version: "1.0.0" } },
  docs: {
    path: "/reference",              // por defecto: "/docs"
    openapiPath: "/spec.json",       // por defecto: "/openapi.json"
    openapiYamlPath: "/spec.yaml",   // por defecto: "/openapi.yaml"; false lo desactiva
    ui: "scalar",                     // "scalar" (por defecto) | "swagger" | "redoc"
    scalar: {
      theme: "kepler",
      customCss: ":root { --scalar-color-accent: #2563eb; }",
      hideTestRequestButton: true,
    },
    tags: ["Docs"],                   // por defecto: ["Docs"]; pasa [] para omitirlas
    enabled: "auto",                  // por defecto "auto" (desactivado en producción); true | false
  },
});
```

<blockquote><strong>Seguridad:</strong> una especificación publicada es un mapa completo de tu superficie de ataque: cada ruta, parámetro, esquema de autenticación y forma de error. Con <code>docs: true</code> o <code>enabled: true</code> en producción, DaloyJS registra <code>docs.public_in_production</code> y sirve la especificación a cualquiera que pueda alcanzarla. Eso es correcto para una API pública. Para cualquier otro caso, deja <code>"auto"</code> o protege la documentación con autenticación (un <code>bearerAuth()</code> a nivel de aplicación sin un <code>except()</code> para <code>/docs</code> ni <code>/openapi.json</code> las cubre). Marca las rutas de administración, de tareas programadas y de depuración con <code>internal: true</code>. Así quedan fuera del documento generado y responden <code>404</code> al tráfico de red, mientras que <code>app.inject()</code> sigue pudiendo llamarlas. Consulta <a href="/docs/security/admin-panels">Secure admin panels</a> (en inglés).</blockquote>

## Elige una interfaz: Scalar, Swagger UI o Redoc [#pick-a-ui-scalar-swagger-ui-or-redoc]

Define `ui` como `"scalar"` (valor por defecto), `"swagger"` o `"redoc"`. Las tres interfaces muestran la misma especificación en vivo, se montan en las mismas rutas y cargan los mismos recursos alojados en CDN. Scalar y Swagger UI usan la misma CSP estricta, mientras que Redoc la amplía con `worker-src 'self' blob:` para su índice de búsqueda. Aun así, cambiar de una a otra es un cambio de una sola palabra. Scalar y Swagger UI incluyen una consola de peticiones para desarrolladores en las rutas protegidas. Redoc es una interfaz de referencia de solo lectura: muestra los requisitos de seguridad, pero no incluye una consola integrada *Try it*.

```ts
new App({
  openapi: { info: { title: "My API", version: "1.0.0" } },
  docs: {
    ui: "swagger",
    swagger: {
      docExpansion: "none",
      displayRequestDuration: true,
    },
  },
});
```

Swagger UI conserva las autorizaciones de su diálogo *Authorize* entre recargas de forma predeterminada. Para ello, guarda el token pegado en el `localStorage` del navegador, al igual que Scalar con `persistAuth: true`. Cualquier script que se ejecute en el origen de la documentación puede leerlo, y sobrevive a cerrar la pestaña. Pega solo tokens de prueba de vida corta y con los permisos mínimos, nunca credenciales de producción ni de administrador, y sirve la documentación desde un origen distinto al de cualquier aplicación web propia. Pasa `swagger: { persistAuthorization: false }` para mantener los tokens solo en memoria. Scalar selecciona automáticamente el primer esquema de seguridad de OpenAPI configurado, así que el formulario de autenticación está listo para que los desarrolladores peguen un token bearer o una clave de API. Si quieres un valor predeterminado distinto para Scalar, defínelo de forma explícita:

```ts
new App({
  openapi: {
    info: { title: "My API", version: "1.0.0" },
    securitySchemes: {
      bearer: { type: "http", scheme: "bearer", bearerFormat: "JWT" },
      apiKey: { type: "apiKey", in: "header", name: "x-api-key" },
    },
  },
  docs: {
    scalar: {
      persistAuth: true,
      authentication: { preferredSecurityScheme: "bearer" },
    },
  },
});
```

Si tu documentación necesita un punto de acceso visible para iniciar sesión, añade `docs.auth`. El mismo botón se muestra para Scalar, Swagger UI y Redoc. Apúntalo a un formulario de inicio de sesión local, a una ruta de Better Auth, a una URL de inicio de sesión de Clerk o a una URL de autorización de OIDC de Auth0, Okta, Microsoft Entra ID, Cognito, Keycloak u otro proveedor:

```ts
new App({
  openapi: {
    info: { title: "My API", version: "1.0.0" },
    securitySchemes: {
      oidc: {
        type: "oauth2",
        flows: {
          authorizationCode: {
            authorizationUrl: "https://login.example.com/oauth2/v2.0/authorize",
            tokenUrl: "https://login.example.com/oauth2/v2.0/token",
            scopes: { "api.read": "Read API data" },
          },
        },
      },
    },
  },
  docs: {
    ui: "redoc", // también funciona con "scalar" y "swagger"
    auth: {
      loginUrl: "/login", // o la URL de autorización / inicio de sesión de tu proveedor
      label: "Sign in",
      target: "popup",
    },
  },
});
```

El objeto `redoc` se reenvía sin modificar a `Redoc.init(specUrl, configuration, element)`. Como Redoc construye su índice de búsqueda en un Web Worker de tipo `blob:`, la ruta `/docs` montada automáticamente amplía la CSP de esa página con `worker-src 'self' blob:` solo para `ui: "redoc"`. Scalar y Swagger UI mantienen la política más restrictiva. La opción `scalar` se ignora salvo que `ui` sea `"scalar"`, y lo mismo ocurre con `swagger` y `redoc`.

El objeto `scalar` se reenvía a la API HTML de Scalar como configuración en JSON, mientras que Daloy mantiene la ruta `openapiPath` en vivo como fuente. Úsalo para temas, CSS personalizado, diseño, valores predeterminados de autenticación y visibilidad del cliente, sin copiar el HTML de la documentación.

## Avanzado: genera la especificación a mano [#advanced-generate-the-spec-manually]

¿Necesitas el objeto de especificación sin procesar (para generación de código, pruebas de contrato o una ruta personalizada)? Llama directamente a `generateOpenAPI(app, options)`:

```ts
import { generateOpenAPI } from "@daloyjs/core/openapi";

const doc = generateOpenAPI(app, {
  info: { title: "My API", version: "1.0.0" },
  servers: [{ url: "https://api.example.com" }],
  securitySchemes: { bearer: { type: "http", scheme: "bearer" } },
});

console.log(JSON.stringify(doc, null, 2));
```

## Avanzado: sirve la documentación desde tu propia ruta [#advanced-serve-docs-from-your-own-route]

Una ruta de documentación escrita a mano es una ruta normal, así que el control de `docs: "auto"` no se aplica a ella. Decide tú si debe existir en producción y si necesita autenticación. Lo mismo vale para cualquier ruta `/openapi.json` que sirvas a mano con `generateOpenAPI()`:

```ts
import { swaggerUiHtml, scalarHtml, redocHtml, htmlResponse } from "@daloyjs/core/docs";

// `docs: "auto"` no la cubre, así que protégela tú.
if (process.env.NODE_ENV !== "production") {
  app.get(
    "/docs",
    {
      operationId: "docs",
      responses: { 200: { description: "API reference" } },
    },
    async () => {
      const html = scalarHtml({
        specUrl: "/openapi.json",
        title: "My API",
        configuration: { theme: "kepler" },
      });
      const res = htmlResponse(html);
      return { status: 200, body: await res.text(), headers: Object.fromEntries(res.headers) };
    },
  );
}
```

`swaggerUiHtml`, `scalarHtml` y `redocHtml` devuelven páginas HTML autocontenidas que cargan sus recursos desde jsDelivr, con una CSP estricta que solo permite ese origen. Si escribes la ruta a mano con `redocHtml`, pasa `allowBlobWorkers: true` a `htmlResponse` (o a `docsContentSecurityPolicy`) para que la CSP permita el worker de búsqueda `blob:` de Redoc:

```ts
import { redocHtml, htmlResponse } from "@daloyjs/core/docs";

const res = htmlResponse(
  redocHtml({ specUrl: "/openapi.json", title: "My API", configuration: { hideDownloadButtons: true } }),
  { allowBlobWorkers: true },
);
```

Si quieres probar la experiencia de tu documentación con un contrato mucho más grande, consulta la [demo de API REST falsa a gran escala](/docs/tutorials/fake-rest-api) (en inglés). Es una referencia más útil que un CRUD de juguete cuando necesitas validar la búsqueda, la agrupación y el rendimiento de renderizado.

## Vuélcala a disco para la generación de código [#dump-to-disk-for-codegen]

```ts
// scripts/dump-openapi.ts
import { writeFile, mkdir } from "node:fs/promises";
import { dirname } from "node:path";
import { generateOpenAPI } from "@daloyjs/core/openapi";
import { buildApp } from "../src/build-app.js";

const app = buildApp();
const out = "./generated/openapi.json";
await mkdir(dirname(out), { recursive: true });
await writeFile(out, JSON.stringify(generateOpenAPI(app, {
  info: { title: "My API", version: "1.0.0" },
}), null, 2));
console.log(`wrote ${out}`);
```

```json
// package.json
"scripts": {
  "gen:openapi": "node scripts/dump-openapi.ts"
}
```

## Qué se emite [#what-gets-emitted]

- Un `operationId` por ruta. Los duplicados lanzan un error durante el registro.
- Los parámetros de ruta `:id` se normalizan a `{id}`.
- Los cuerpos de esquema se convierten mediante `schema.toJSONSchema?.()` cuando está disponible, o mediante un respaldo estructural.
- `components.schemas.Problem` reutilizable para los errores RFC 9457.
- Los esquemas etiquetados con un id (`.meta({ id: "Book" })`) se elevan a `components.schemas` y se referencian mediante `$ref` (consulta [Esquemas con nombre](#named-schemas)).
- `tags`, `summary`, `description` y `description` por código de estado.
- Las rutas marcadas con `internal: true` se omiten, salvo que pases `includeInternal: true` (por ejemplo, un contrato solo interno para tus propias herramientas). Nunca publiques ese documento.

## Esquemas con nombre y `components.schemas` [#named-schemas]

Por defecto, cada esquema de petición y de respuesta se incluye en línea dentro de la operación que lo usa. Es correcto, pero un cliente generado nombra entonces los tipos según la operación (`GetBookResponse`, `ListBooksResponse[number]`), y la misma forma se repite en cada operación que la devuelve.

Si asignas un id a un esquema, DaloyJS lo emite **una sola vez** en `components.schemas` y lo referencia mediante `$ref` en todos los lugares donde aparece, incluidos otros esquemas con nombre, los esquemas de parámetros de ruta y de consulta, los webhooks y los callbacks:

```ts
import { z } from "zod";

export const Book = z
  .object({ id: z.string(), title: z.string() })
  .strict()
  .meta({ id: "Book" });

export const Author = z
  .object({ name: z.string(), books: z.array(Book) })
  .strict()
  .meta({ id: "Author" });

app.get("/books/:id", { responses: { 200: { body: Book } } }, getBook);
app.get("/authors", { responses: { 200: { body: z.array(Author) } } }, listAuthors);
```

```json
{
  "paths": {
    "/books/{id}": { "get": { "responses": { "200": { "content": { "application/json": {
      "schema": { "$ref": "#/components/schemas/Book" } } } } } } },
    "/authors": { "get": { "responses": { "200": { "content": { "application/json": {
      "schema": { "type": "array", "items": { "$ref": "#/components/schemas/Author" } } } } } } } }
  },
  "components": {
    "schemas": {
      "Problem": { "...": "..." },
      "Book": { "type": "object", "properties": { "id": { "type": "string" }, "title": { "type": "string" } }, "required": ["id", "title"], "additionalProperties": false },
      "Author": { "type": "object", "properties": { "name": { "type": "string" }, "books": { "type": "array", "items": { "$ref": "#/components/schemas/Book" } } }, "required": ["name", "books"], "additionalProperties": false }
    }
  }
}
```

Hey API (y cualquier otro generador de clientes para OpenAPI) ahora produce un tipo `Book` y un tipo `Author` que puedes importar directamente, en lugar de una forma anónima por operación. Así no hace falta mantener a mano un `models.ts` que renombre los tipos generados.

Reglas:

- **Los ids deben ser únicos por forma.** Dos esquemas con estructuras distintas que compartan un mismo id hacen que `generateOpenAPI()` lance un error, porque el segundo reemplazaría en silencio al primero en todos los clientes generados. Reutiliza la misma instancia del esquema o asigna al segundo un id propio.
- **`Problem` está reservado** para el esquema de error RFC 9457 integrado.
- Las claves `$defs` y `$schema` propias de Zod 4 nunca llegan al documento: el dialecto ya lo define OpenAPI 3.1 para todo el documento, y los punteros `#/$defs/...` se reescriben como `#/components/schemas/...` para que ninguna referencia quede colgando.
- Los esquemas sin id siguen incluyéndose en línea, como antes.

Zod es aquí la implementación de referencia (`.meta({ id })` es lo que hace que `toJSONSchema()` emita `$defs`). Cualquier biblioteca de Standard Schema cuyo `toJSONSchema()` devuelva la misma forma `{ $ref, $defs }` se eleva de la misma manera.

## Webhooks [#webhooks]

OpenAPI 3.1 permite que un productor publique **webhooks de nivel superior**: operaciones que se espera que un consumidor implemente. Pasa `webhooks` a `generateOpenAPI` y DaloyJS los emitirá dentro del mapa `webhooks` de nivel superior del documento.

```ts
import { generateOpenAPI } from "@daloyjs/core/openapi";

const doc = generateOpenAPI(app, {
  info: { title: "Books", version: "1.0.0" },
  webhooks: {
    bookCreated: {
      method: "POST",
      operationId: "onBookCreated",
      summary: "Fires when a book is created",
      tags: ["Webhooks"],
      request: { body: z.object({ id: z.string(), title: z.string() }) },
      responses: { 200: { description: "Acknowledged" } },
      auth: { scheme: "bearer", scopes: ["webhook:receive"] },
    },
  },
});
```

El mapa `webhooks` solo *describe* la operación; no entrega ni protege nada. Para entregas reales, firma cada carga útil para que los receptores puedan verificar tanto el origen como la integridad, e incluye una marca de tiempo para que puedan rechazar las repeticiones (replays). Un token bearer estático, por sí solo, no prueba ninguna de las dos cosas. [`createWebhookSender()`](/docs/webhook-delivery) (en inglés) firma, añade la marca de tiempo, reintenta y enruta cada petición saliente a través de `fetchGuard()`. Los receptores verifican con `verifyWebhookSignature()`. Documenta las cabeceras de firma en la `description` del webhook.

## Callbacks [#callbacks]

Los **callbacks** describen peticiones fuera de banda que una operación puede desencadenar en el consumidor (por ejemplo, un endpoint de suscripción que más tarde hace un POST a la URL que indicó quien hizo la llamada). Adjunta un mapa `callbacks` directamente a una ruta o a un webhook.

```ts
import { fetchGuard } from "@daloyjs/core";

// Toda petición a una URL indicada por quien llama pasa por la protección contra SSRF.
const safeFetch = fetchGuard();

app.post(
  "/subscribe",
  {
    operationId: "subscribe",
    request: {
      body: z
        .object({
          // solo https: rechaza file:, gopher:, javascript: y http: simple
          callbackUrl: z.url({ protocol: /^https$/ }),
        })
        .strict(),
    },
    responses: { 201: { description: "Subscribed" } },
    callbacks: {
      onEvent: {
        "{$request.body#/callbackUrl}": {
          method: "POST",
          operationId: "onEventCallback",
          request: { body: z.object({ id: z.string() }) },
          responses: {
            200: { description: "ack" },
            410: { description: "gone" },
          },
        },
      },
    },
  },
  async () => ({ status: 201, body: undefined }),
);
```

<blockquote><strong>Seguridad:</strong> una URL de callback suministrada por quien hace la llamada es un punto de Server-Side Request Forgery (SSRF). La validación del esquema no basta. <code>z.url()</code> por sí solo acepta <code>http://169.254.169.254/</code> (metadatos de la nube), <code>http://localhost:6379/</code> y URLs <code>file:</code> o <code>gopher:</code>, e incluso <code>{"z.url({ protocol: /^https$/ })"}</code> sigue aceptando <code>https://169.254.169.254/</code> o un nombre de host que se resuelve a una dirección privada. Envía cada callback a través de <code>safeFetch</code> desde <a href="/docs/security/fetch-guard"><code>fetchGuard()</code></a> (en inglés), que comprueba la dirección resuelta y cada redirección. Mejor aún, entrega con <a href="/docs/webhook-delivery"><code>createWebhookSender()</code></a> (en inglés), que además firma la carga útil. Considera verificar la propiedad de la URL, por ejemplo con una petición de desafío, antes de almacenarla.</blockquote>

Cada nombre de callback se asigna a una o más claves de expresión en tiempo de ejecución (por ejemplo, `"{$request.body#/callbackUrl}"`), y cada una de ellas se asigna a una o más operaciones indexadas por método HTTP. Los mapas vacíos y los arrays vacíos se omiten, así que pasar un callback vacío nunca produce una especificación mal formada.

## Uniones discriminadas [#discriminated-unions]

El `discriminator` de OpenAPI 3.1 es la forma canónica de describir las uniones etiquetadas. DaloyJS incluye dos helpers en `@daloyjs/core/openapi` (y en el paquete raíz):

- `discriminator(propertyName, mapping?)`: el constructor básico de la especificación. Úsalo cuando ya tienes un JSON Schema escrito a mano y quieres añadir el campo de forma limpia.
- `discriminatedUnion(propertyName, variants, opts?)`: un envoltorio compatible con Standard Schema que *tanto* valida en tiempo de ejecución (despachando según el valor del discriminador) *como* expone `.toJSONSchema()`, de modo que el generador de OpenAPI emite `{ oneOf, discriminator }` automáticamente.

```ts
import { z } from "zod";
import { discriminatedUnion } from "@daloyjs/core";

// .strict() rechaza con un 422 las claves desconocidas (por ejemplo, un `isAdmin` inyectado)
// en lugar de eliminarlas en silencio.
const Cat = z.object({ kind: z.literal("cat"), meow: z.boolean() }).strict();
const Dog = z.object({ kind: z.literal("dog"), bark: z.boolean() }).strict();

const Animal = discriminatedUnion(
  "kind",
  { cat: Cat, dog: Dog },
  { mapping: { cat: "#/components/schemas/Cat", dog: "#/components/schemas/Dog" } },
);

app.post(
  "/animals",
  {
    operationId: "createAnimal",
    request: { body: Animal },
    responses: { 201: { description: "ok", body: Animal } },
  },
  async ({ body }) => ({ status: 201, body }),
);
```

En tiempo de ejecución, el envoltorio rechaza los valores que no son objetos, los discriminadores ausentes o que no son cadenas, y los valores de discriminador desconocidos (incluidos los nombres heredados como `__proto__`, `constructor` y `toString`) con un problema de Standard Schema claro. Después delega en el validador de la variante correspondiente todo lo demás.
