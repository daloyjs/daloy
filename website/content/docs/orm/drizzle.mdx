# Use Drizzle ORM with DaloyJS

[Drizzle ORM](https://orm.drizzle.team) is a lightweight, TypeScript-native ORM with a SQL-like API. It runs everywhere DaloyJS does, including Cloudflare Workers, and infers result types directly from your schema.

## 1. Install

```bash
pnpm add drizzle-orm postgres
pnpm add -D drizzle-kit
```

<Callout type="note">This guide targets the current stable line (`drizzle-orm@latest`, 0.45 at the time of writing). Drizzle 1.0 is in release candidate (`drizzle-orm@rc`) and brings Relational Queries v2, which defines relations with `defineRelations()` and passes them as `drizzle({ client, relations })`. Follow Drizzle's v1 upgrade guide if you adopt the RC.</Callout>

## 2. Define your schema

```ts title="src/db/schema.ts"
import { pgTable, uuid, text, timestamp } from "drizzle-orm/pg-core";

export const users = pgTable("users", {
  id: uuid("id").defaultRandom().primaryKey(),
  email: text("email").notNull().unique(),
  name: text("name"),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
```

```ts title="drizzle.config.ts"
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  schema: "./src/db/schema.ts",
  out: "./drizzle",
  dialect: "postgresql",
  dbCredentials: { url: process.env.DATABASE_URL! },
});
```

Generate migrations in development and apply them as a deploy step, never at app boot (see [migrations](/docs/orm#migrations)):

```bash
pnpm drizzle-kit generate
pnpm drizzle-kit migrate
```

## 3. Create a Drizzle plugin

```ts title="src/db/drizzle.ts"
import postgres from "postgres";
import { drizzle } from "drizzle-orm/postgres-js";
import type { App } from "@daloyjs/core";
import * as schema from "./schema.ts";

// Add `prepare: false` only behind a transaction-mode pooler
// (PgBouncer in transaction mode, Supabase's transaction pooler).
const client = postgres(process.env.DATABASE_URL!, { max: 10 });
export const db = drizzle({ client, schema });

// Call with the root app, not through app.register(): a decoration made
// inside a registered plugin is visible only to that plugin's own routes.
export function drizzlePlugin(app: App) {
  app.decorate("db", db);
  app.onClose(async () => {
    await client.end({ timeout: 5 });
  });
}
```

`onClose()` runs on the Node.js, Bun, and Deno adapters only. On Lambda, Vercel, or Azure Functions keep `max` at 1 or close to it, and on Workers build the client per request; see [Serverless and edge lifecycle](/docs/orm#serverless-lifecycle).

## 4. Augment app state types

Add the `declare module` block to the same module that exports `db`, not to a separate `.d.ts` file. Declaration files are exempt from type-checking when `skipLibCheck` is on (the scaffolded default), so a broken import inside a `.d.ts` fails silently and `state.db` degrades to `any`.

```ts title="src/db/drizzle.ts"
// same module as the plugin above
declare module "@daloyjs/core" {
  interface AppState {
    db: typeof db;
  }
}
```

## 5. Use it in routes

```ts title="src/server.ts"
import { z } from "zod";
import { eq } from "drizzle-orm";
import { App, NotFoundError } from "@daloyjs/core";
import { serve } from "@daloyjs/core/node";
import { drizzlePlugin } from "./db/drizzle.ts";
import { users } from "./db/schema.ts";

const app = new App();
drizzlePlugin(app);

// Dates go over the wire as ISO strings: z.coerce.date() has no
// representation in the generated OpenAPI document.
const UserSchema = z.object({
  id: z.uuid(),
  email: z.email(),
  name: z.string().nullable(),
  createdAt: z.iso.datetime(),
});

type UserRow = typeof users.$inferSelect;
const toUser = (row: UserRow) => ({ ...row, createdAt: row.createdAt.toISOString() });

app.get(
  "/users/:id",
  {
    operationId: "getUser",
    request: { params: z.object({ id: z.uuid() }) },
    responses: {
      200: { description: "Found", body: UserSchema },
      404: { description: "Not found" },
    },
  },
  async ({ params, state }) => {
    const [user] = await state.db.select().from(users).where(eq(users.id, params.id)).limit(1);
    if (!user) throw new NotFoundError("User not found");
    return { status: 200, body: toUser(user) };
  },
);

app.post(
  "/users",
  {
    operationId: "createUser",
    request: { body: z.object({ email: z.email(), name: z.string().optional() }) },
    responses: { 201: { description: "Created", body: UserSchema } },
  },
  async ({ body, state }) => {
    // Safe only because z.object() strips unknown keys (no mass assignment).
    const [created] = await state.db.insert(users).values(body).returning();
    return { status: 201, body: toUser(created) };
  },
);

await app.ready();
serve(app, { port: 3000 });
```

## Transactions

This example assumes `orders` and `inventory` tables in `schema.ts` and a route that declares `201`. Throwing inside the callback rolls back.

```ts
import { eq, sql } from "drizzle-orm";
import { inventory, orders } from "./db/schema.ts";

handler: async ({ body, state }) => {
  const order = await state.db.transaction(async (tx) => {
    const [created] = await tx.insert(orders).values({ sku: body.sku, qty: body.qty }).returning();
    await tx
      .update(inventory)
      .set({ stock: sql`${inventory.stock} - ${body.qty}` })
      .where(eq(inventory.sku, body.sku));
    return created;
  });
  return { status: 201, body: order };
}
```

Interactive `db.transaction()` needs a driver that holds a database session open. The Neon HTTP driver (`drizzle-orm/neon-http`) and Cloudflare D1 do not: use `db.batch([...])` there, which runs the statements as one atomic batch, or switch to the WebSocket-based `drizzle-orm/neon-serverless` driver with a `Pool` when you need interactive transactions on Neon.

## Edge runtimes

Drizzle is the easiest path to running DaloyJS against a real database on the edge. Pick a driver:

- Cloudflare Workers + D1: `drizzle-orm/d1`
- Cloudflare Workers + Postgres through [Hyperdrive](/docs/databases/hyperdrive): `drizzle-orm/postgres-js` (or `drizzle-orm/node-postgres`) with a client created per request. Keep prepared statements on with Hyperdrive.
- Neon (Postgres) over HTTP on any edge: `drizzle-orm/neon-http`
- PlanetScale (MySQL): `drizzle-orm/planetscale-serverless`

```ts title="src/worker.ts"
// Cloudflare Workers + D1
import { env } from "cloudflare:workers";
import { drizzle } from "drizzle-orm/d1";
import { App } from "@daloyjs/core";
import { toFetchHandler } from "@daloyjs/core/cloudflare";
import * as schema from "./db/schema.ts";

// `wrangler types` generates the global `Env` interface from your wrangler
// config, which types `env.DB` as a D1 binding.
const app = new App();

// A D1 binding is not a socket, so one Drizzle instance can serve every
// request. Decorate once, before the routes: calling decorate() inside the
// Worker fetch handler throws on the second request. Drizzle's D1 docs pass
// the binding as the first argument rather than as `{ client }`.
app.decorate("db", drizzle(env.DB, { schema }));

// ...register routes that read state.db

export default toFetchHandler(app);
```

For Hyperdrive, build the client in a hook instead, as shown in [Serverless and edge lifecycle](/docs/orm#serverless-lifecycle).

Compare with [Prisma](/docs/orm/prisma), [TypeORM](/docs/orm/typeorm), [MikroORM](/docs/orm/mikro-orm), [Sequelize](/docs/orm/sequelize), [Supabase](/docs/orm/supabase), or the [ODM overview](/docs/odm) for document databases.

Drizzle pairs cleanly with every host in the [database hosting overview](/docs/databases), including [Neon](/docs/databases/neon), [PlanetScale](/docs/databases/planetscale), [Turso](/docs/databases/turso), and [Cloudflare D1](/docs/databases/cloudflare-d1).
