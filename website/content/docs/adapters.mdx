# Adapters & runtimes

DaloyJS is a REST API backend framework. The core only ever sees `Request → Response`. Runtime-specific concerns, sockets, signals, edge handlers, Lambda event shapes, live in thin adapters at the edge. Choose the adapter for the place you want to deploy your API.

## Pick a target

### Runtimes (you own the process)

<Cards>
<Card title="Node.js" href="/docs/adapters/node">Long-lived process on Node 24 LTS or Node 26+. Sane request/header/keep-alive timeouts and SIGTERM-driven graceful shutdown.</Card>
<Card title="Bun" href="/docs/adapters/bun">Native Bun.serve for REST APIs. Fast startup, built-in TLS, Unix sockets, and hot reload in dev.</Card>
<Card title="Deno" href="/docs/adapters/deno">Stable Deno.serve with built-in signal handling. Self-host in a container; Deno Deploy shuts down around April 2027.</Card>
</Cards>

### Edge & serverless (platform owns the process) [#edge-and-serverless-platform-owns-the-process]

<Cards>
<Card title="Cloudflare Workers" href="/docs/adapters/cloudflare-workers">Modules-format Worker with bindings for KV, R2, D1, DO, Queues, Hyperdrive. Also runs self-hosted on workerd.</Card>
<Card title="Vercel" href="/docs/adapters/vercel">Vercel Functions on Fluid compute, or mounted inside a Next.js App Router route handler.</Card>
<Card title="Netlify" href="/docs/adapters/netlify">Edge Functions (Deno) and Functions v2 (Node, fetch-style). The v1 lambda shape is legacy.</Card>
<Card title="Fastly Compute" href="/docs/adapters/fastly">JS Compute via @fastly/js-compute and the fetch-event listener model, wrapped by installFastlyListener.</Card>
<Card title="AWS Lambda" href="/docs/adapters/aws-lambda">API Gateway HTTP API v2.0, REST API v1.0, Function URLs behind CloudFront, and streamifyResponse for streaming.</Card>
<Card title="Azure Functions" href="/docs/adapters/azure-functions">Node.js v4 programming model. One catch-all HTTP trigger, cookies mapped for you, optional HTTP streams.</Card>
</Cards>

Containers on Google Cloud Run, Fly.io, Render, Railway, or Kubernetes use the Node adapter. See [Deployment](/docs/deployment).

## What each adapter gives you [#capabilities]

Every adapter runs the same routing, validation, security headers, and problem+json errors. What differs is what the platform hands the adapter:

| Adapter | Real client peer | Streaming responses | WebSockets (`app.ws`) | Graceful shutdown | OTLP telemetry flush |
| --- | --- | --- | --- | --- | --- |
| Node (`/node`) | Yes, from the socket | Yes | Yes | `SIGTERM`/`SIGINT` | Interval + on shutdown |
| Bun (`/bun`) | Yes, from the socket | Yes | Yes | `SIGTERM`/`SIGINT` | Interval + on shutdown |
| Deno (`/deno`) | Yes, from the socket | Yes | No | `SIGTERM`/`SIGINT` | Interval + on shutdown |
| Cloudflare Workers, workerd (`/cloudflare`) | No, use `behindProxy` | Yes | No | Platform-managed | Per request via `ctx.waitUntil` |
| Vercel, Netlify v2 / Edge (`/vercel`) | No, use `behindProxy` | Yes | No | Platform-managed | Per request via `waitUntil` when present |
| Fastly Compute (`/fastly`) | No, use `behindProxy` | Yes | No | Platform-managed | Per request via `event.waitUntil` |
| AWS Lambda (`/lambda`) | Yes, from the event | Buffered, or `toLambdaStreamHandler` | No | Platform-managed | Awaited before returning |
| Azure Functions (`/azure`) | No, use `behindProxy` | Buffered, or `stream: true` | No | Platform-managed | Awaited before returning |

- **Real client peer** is what `getConnInfo(ctx.request)` returns. It never comes from a header a client could fake. Where the platform does not expose it, declare `behindProxy` so `rateLimit()` and `resolveClientIp()` read the platform's `X-Forwarded-For`. See [Reverse proxy](/docs/deployment#reverse-proxy).
- **Graceful shutdown** means the adapter drains your `app.onShutdown` hooks on a signal. On platform-managed hosts your code is never sent `SIGTERM`, so do not rely on shutdown hooks there.

The Node adapter runs the whole test suite. Deno, Bun, and workerd also run a smoke suite on the real runtime binaries in CI, against the published `dist/` build, on every change.

## Roll your own

If your runtime exposes the web-standard `Request / Response` contract and isn't listed above, you don't need an adapter at all, pass the incoming request straight to `app.fetch`:

```ts
// modules-format (Cloudflare Workers, Deno, Bun, etc.)
export default {
  fetch(request: Request): Promise<Response> {
    return app.fetch(request);
  },
};
```
