# Installation

DaloyJS targets **Node.js 24 LTS or Node.js 26 and newer** (`engines.node`: `^24.0.0 || >=26.0.0`) and is distributed on the public npm registry as `@daloyjs/core`. The package has **no peer dependencies**, so `npm`, `yarn`, `pnpm`, and `bun` can all install it directly. We *recommend* [pnpm](https://pnpm.io/motivation) together with the hardened `.npmrc` defaults below for supply-chain reasons, but it is not required. The `engines.pnpm` entry in `package.json` is advisory metadata, while `engines.node` communicates the supported runtime and may warn or fail depending on your package manager and engine-strict settings.

## Fastest path: scaffold a project

Use the official generator, it sets up a hardened `.npmrc`, strict TypeScript, and a working route in one command.

Package links: [create-daloy on npm](https://www.npmjs.com/package/create-daloy) and [@daloyjs/core on npm](https://www.npmjs.com/package/@daloyjs/core).

```bash
# choose one package manager
pnpm create daloy@latest my-api
npm  create daloy@latest my-api
yarn create daloy           my-api
bun  create daloy           my-api
```

See [Scaffold a project](/docs/scaffolder) for templates and flags.

## Or install into an existing project

### Prerequisites

- **Node.js** 24 LTS, or 26.0.0 and newer (Node.js 25 is not supported).
- **TypeScript** 7 or 6. DaloyJS is built with TypeScript 7, and CI checks that apps on TypeScript 6 compile against the published types (see [TypeScript versions](#typescript-versions)).
- A package manager. Any of these works, pnpm 11.x or newer is recommended for supply-chain hardening, but `npm`, `yarn`, and `bun` install `@daloyjs/core` cleanly because the package has no peer dependencies.

To enable pnpm via [Corepack](https://nodejs.org/api/corepack.html):

```bash
corepack enable
corepack prepare pnpm@11.1.3 --activate
pnpm --version
```

## TypeScript versions [#typescript-versions]

`@daloyjs/core` ships compiled JavaScript plus `.d.ts` files and has no `typescript` peer dependency, so the TypeScript version is your app's choice:

| Your app | Status |
| --- | --- |
| TypeScript 7 (native compiler) | Supported. The framework is developed and type-checked on it, and `create-daloy` templates default to it. |
| TypeScript 6 | Supported. The `verify:ts-consumer-compat` CI gate type-checks every public subpath and the type-level tests on TypeScript 6 against the TypeScript 7 build. |
| TypeScript 5.9 | Used by the `vercel` template only, because Vercel's Node builder needs the TypeScript JavaScript API and its CLI declares a `typescript` 4 or 5 peer. |

Choose TypeScript 6 when a tool in your stack loads `typescript` as a library. TypeScript 7 removed that JavaScript API, so those tools cannot run on it yet.

<Callout type="warning" title="Hey API and TypeScript 7">
The stable `@hey-api/openapi-ts` releases (0.99.x) drive the TypeScript compiler API and crash on TypeScript 7 with `Cannot read properties of undefined (reading 'AnyKeyword')`. The pinned `0.0.0-next-20260930190945` snapshot does not depend on TypeScript, generates the same client on TypeScript 6 and 7, and is what the templates use. Pin it exactly; a range or a Dependabot bump would move you to the stable line. If you stay on TypeScript 6 you may use stable `0.99.x` instead, but then pin `js-yaml` to `^4.3.2` (its bundled 4.2.0 has three high-severity advisories) and switch back to the snapshot before you upgrade to TypeScript 7.
</Callout>

## Hardened install settings [#hardened-npmrc]

On pnpm 11+, put the supply-chain settings in `pnpm-workspace.yaml` in your project root (camelCase keys; pnpm 11 reads this file even in a single-package project). pnpm 11 ignores these settings in `.npmrc`, so an `.npmrc`-only setup does not get the cooldown or the script policy.

```yaml title="pnpm-workspace.yaml"
minimumReleaseAge: 1440
blockExoticSubdeps: true
ignoreScripts: true
strictPeerDependencies: true
verifyStoreIntegrity: true
preferFrozenLockfile: true
autoInstallPeers: true
```

For npm and older pnpm versions, keep the same values in `.npmrc` as well:

```ini title=".npmrc"
auto-install-peers=true
strict-peer-dependencies=true
prefer-frozen-lockfile=true
verify-store-integrity=true
minimum-release-age=1440
ignore-scripts=true
```

The cooldown and `ignoreScripts` reduce supply-chain risk for these installs; they do not stop every attack. `ignoreScripts` blocks install-script payloads, not code that runs when a package is imported, and the 24-hour cooldown only helps against compromises that are caught within a day.

Read the rationale in [Security](/docs/security) and the [pnpm motivation guide](https://pnpm.io/motivation).

## Verify

Run this from the project root after installing, it works the same under pnpm, npm, yarn, or bun because it shells straight to `node`:

```bash
node -e "import('@daloyjs/core').then(m => console.log('DaloyJS ok ->', Object.keys(m).slice(0, 6)))"
```
